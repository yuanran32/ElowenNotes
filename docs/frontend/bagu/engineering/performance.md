# 性能优化

## 一句话结论

前端性能优化要先度量再优化。首屏慢通常从网络资源、JS 执行、渲染阻塞、接口耗时和缓存策略几个方向排查。

## 常用指标

| 指标 | 含义 | 优化方向 |
| --- | --- | --- |
| FCP | 首次内容绘制 | 减少阻塞资源、优化 HTML/CSS |
| LCP | 最大内容绘制 | 优化首屏大图、主内容、服务端响应 |
| CLS | 累积布局偏移 | 固定图片尺寸、避免异步插入挤压 |
| INP | 交互响应延迟 | 减少长任务、拆分重计算 |
| TTFB | 首字节时间 | CDN、缓存、服务端性能 |

## 排查顺序

1. 用 Lighthouse、Performance、Network 看瓶颈。
2. 看资源体积：JS、CSS、图片、字体是否过大。
3. 看加载瀑布：是否有阻塞请求、串行请求、缓存失效。
4. 看主线程：是否有长任务、大量同步计算、频繁布局。
5. 看业务接口：首屏是否等待了非必要接口。

## 常见优化手段

| 方向 | 做法 |
| --- | --- |
| 资源体积 | Tree Shaking、压缩、按需引入、图片压缩 |
| 加载时机 | 路由懒加载、组件懒加载、动态 import |
| 缓存 | 静态资源 hash 长缓存、接口缓存、CDN |
| 渲染 | 虚拟列表、减少重排重绘、骨架屏 |
| JS 执行 | 拆长任务、Web Worker、减少重复计算 |

## 首屏优化口径

可以这样回答：

“我会先用 Performance 和 Network 定位瓶颈。如果是 JS 包大，就做路由懒加载、依赖拆包和按需引入；如果是图片慢，就做压缩、WebP/AVIF、响应式图片和 CDN；如果是接口慢，就区分首屏必要数据和非必要数据，必要数据加缓存或并发，非必要数据延后加载；最后用 LCP、FCP、包体积和加载瀑布验证优化效果。”

## 常见追问

### preload 和 prefetch 区别？

`preload` 用于当前页面马上要用的关键资源，优先级较高；`prefetch` 用于未来页面可能用到的资源，浏览器空闲时加载。滥用 preload 会抢占关键请求，反而拖慢首屏。

### 图片怎么优化？

压缩体积，选择 WebP/AVIF，设置合适尺寸，使用 `srcset/sizes`，首屏关键图可以 preload，非首屏图使用懒加载，并显式设置宽高避免 CLS。

### 长列表怎么优化？

使用虚拟列表，只渲染可视区域和缓冲区节点。还要注意动态高度、滚动定位、键盘访问和列表项状态复用问题。
