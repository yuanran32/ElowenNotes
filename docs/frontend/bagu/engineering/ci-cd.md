# CI/CD

## 一句话结论

CI/CD 的目标是让代码从提交到上线可重复、可检查、可回滚。前端发布不能只靠手动打包上传，需要用流水线统一安装依赖、检查、构建、部署和通知。

## 常见流水线

1. 拉取代码。
2. 安装依赖，使用 lockfile 保证版本一致。
3. 执行 lint、typecheck、unit test。
4. 构建生产产物。
5. 上传静态资源到 CDN 或对象存储。
6. 发布 HTML 或服务端入口。
7. 记录版本，发送通知，接入监控观察。

## 质量门禁

| 门禁 | 作用 |
| --- | --- |
| lint | 统一代码风格，发现明显错误 |
| typecheck | 提前发现类型不匹配 |
| unit test | 保证工具函数和核心逻辑 |
| e2e test | 覆盖核心用户路径 |
| build | 验证生产构建能成功 |
| bundle size | 防止包体积异常增长 |

## 环境管理

前端常见环境包括 development、test、staging、production。环境差异应主要放在环境变量和部署配置中，不应该在业务代码里写大量 `if production` 分支。

```txt
VITE_API_BASE_URL=https://api.example.com
VITE_APP_ENV=production
```

注意：打进前端包里的环境变量对用户可见，不能放密钥。

## 灰度和回滚

灰度发布可以按用户、地区、比例或版本开关逐步放量。回滚要保证两点：

1. 静态资源带 hash，旧版本资源仍可访问。
2. HTML 或入口配置可以快速切回旧版本。

如果只保留最新静态资源，用户缓存中的旧 HTML 可能引用不到旧 JS，导致白屏。

## 常见追问

### 为什么要提交 lockfile？

lockfile 锁定依赖的精确版本，保证本地、CI、线上构建使用同一套依赖。否则同一个 `package.json` 在不同时间安装，可能得到不同子依赖，造成构建或运行差异。

### pnpm 和 npm/yarn 有什么区别？

pnpm 使用内容寻址存储和硬链接/符号链接组织依赖，节省磁盘空间，也能更严格暴露幽灵依赖问题。面试中可以重点讲：它更快、更省空间、依赖结构更严格。

### 前端发布后如何判断是否成功？

看流水线状态只是第一步，还要看线上监控：错误率、白屏率、接口失败率、核心页面性能、用户转化漏斗。发布后观察一段时间，再继续扩大灰度或确认全量成功。
