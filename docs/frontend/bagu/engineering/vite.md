# Vite

## 一句话结论

Vite 开发环境启动快，是因为它利用浏览器原生 ESM，不需要一开始把整个项目打成 bundle；生产环境仍然会用 Rollup 打包，生成适合线上缓存和加载的静态资源。

## Vite 为什么快

| 阶段 | 机制 | 作用 |
| --- | --- | --- |
| 冷启动 | 不全量打包源码 | 避免项目越大启动越慢 |
| 依赖预构建 | esbuild 处理 node_modules | 把 CommonJS 转成 ESM，并合并碎片依赖 |
| 源码加载 | 浏览器按需请求 ESM | 访问到哪个模块才编译哪个模块 |
| HMR | 精确更新变更模块 | 修改组件时不用刷新整个页面 |

## 依赖预构建

Vite 会用 esbuild 预构建第三方依赖。原因有两个：

1. 很多 npm 包仍然包含 CommonJS，浏览器不能直接按 ESM 加载。
2. 某些库有很多细碎模块，浏览器逐个请求会造成网络开销，预构建可以合并依赖。

源码部分通常不预打包，因为源码会频繁变化，需要保持按需编译和快速 HMR。

## Vite 和 Webpack 区别

| 对比项 | Vite | Webpack |
| --- | --- | --- |
| 开发启动 | 基于原生 ESM，按需编译 | 通常先构建依赖图并打包 |
| HMR | 更新粒度更细，链路短 | 依赖 loader 和模块热替换机制 |
| 生产构建 | Rollup | Webpack 自身 |
| 生态 | 现代框架和库支持好 | 老项目、复杂 loader 生态更成熟 |

面试中不要简单说“Vite 一定比 Webpack 好”。更准确的说法是：Vite 在现代 ESM 项目开发体验上优势明显，Webpack 在复杂历史项目、定制 loader、特殊构建链路里仍然常见。

## 常见配置点

```ts
export default defineConfig({
  resolve: {
    alias: {
      '@': '/src',
    },
  },
  build: {
    sourcemap: false,
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router'],
        },
      },
    },
  },
})
```

## 常见追问

### Vite 生产环境为什么还要打包？

开发环境按需加载适合调试，但线上如果保留大量模块请求，会增加网络开销，也不利于压缩、hash 缓存和兼容处理。生产构建需要合并、压缩、分包和生成带 hash 的静态资源。

### HMR 为什么比刷新页面快？

HMR 只替换变更模块，并尽量保留应用状态。比如 Vue 单文件组件改样式时，可以只更新 CSS；改 template 或 script 时，也能通过框架插件做组件级更新。

### Vite 项目首屏慢怎么优化？

Vite 只是构建工具，不能自动解决所有运行时性能问题。首屏慢仍要看路由懒加载、组件体积、图片资源、接口耗时、渲染阻塞和缓存策略。
