# 构建与模块化

## 一句话结论

模块化解决代码组织和依赖管理问题，构建工具负责把模块依赖图转换成浏览器可高效加载的产物。工程化面试要能讲清 ESM、CommonJS、bundle、chunk 的关系。

## 模块规范

| 规范 | 特点 | 常见场景 |
| --- | --- | --- |
| CommonJS | 运行时加载，`require/module.exports` | Node.js、历史 npm 包 |
| ESM | 静态结构，`import/export` | 现代浏览器、现代前端项目 |
| UMD | 兼容多种环境 | 老的第三方库分发 |

ESM 的静态结构更利于 Tree Shaking 和依赖分析，因为构建工具可以在不执行代码的情况下分析导入导出关系。

## 构建工具做什么

1. 从入口文件开始扫描依赖。
2. 通过 loader/plugin 处理 JS、CSS、图片、Vue/SFC 等资源。
3. 构建模块依赖图。
4. 做语法转换、压缩、Tree Shaking、代码分割。
5. 输出带 hash 的静态资源和入口 HTML。

## bundle、chunk、asset

| 概念 | 含义 |
| --- | --- |
| bundle | 打包后的整体产物，常被泛指构建输出 |
| chunk | 按入口、动态导入或手动分包拆出来的代码块 |
| asset | 图片、字体、CSS 等非 JS 或独立资源 |

## 代码分割

```js
const UserPage = () => import('./pages/UserPage.vue')
```

动态导入会让构建工具把对应模块拆成独立 chunk。用户访问到该路由时才加载，可以降低首屏 JS 体积。

## source map

source map 用来把压缩后的线上代码映射回源码，便于定位错误。生产环境是否上传 source map 要结合安全和排障需求：

- 不建议直接公开 `.map` 文件。
- 可以上传到监控平台，用于错误堆栈还原。
- 发布版本号要和 source map 匹配，否则堆栈会映射错。

## 常见追问

### ESM 和 CommonJS 最大区别是什么？

CommonJS 是运行时加载，导出值更像对象拷贝或引用结果；ESM 是编译期静态分析，导入导出关系固定，支持静态优化。ESM 的 `import` 必须在顶层，动态加载要用 `import()`。

### 为什么需要 hash 文件名？

hash 用来做长期缓存。文件内容不变，hash 不变，浏览器可以继续使用缓存；内容变化，hash 变化，浏览器会请求新资源。通常 HTML 不做强缓存，静态资源做长缓存。

### chunk 拆得越细越好吗？

不是。拆太少会导致首屏包过大，拆太细会增加请求数量和调度成本。要结合路由、公共依赖、缓存命中率和真实加载瀑布图取舍。
