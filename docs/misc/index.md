# Misc

这里放不适合归入前端、后端、算法的长期资料。它不是临时垃圾箱，而是“跨主题但值得沉淀”的内容入口。

## 分类原则

1. 能归入明确技术栈的内容，不放 Misc。
2. 一次性备忘但没有复用价值的内容，不放 Misc。
3. 跨领域方法、工具配置、读书笔记、问题复盘和面试杂项，放 Misc。
4. 每篇笔记至少保留来源、结论、适用场景和后续动作。

## 目录

| 分类 | 用途 | 入口 |
| --- | --- | --- |
| 文章沉淀 | 技术文章、博客、论文、资料读后整理 | [articles](./articles/) |
| 读书笔记 | 书籍章节总结、核心观点、可实践清单 | [books](./books/) |
| 工具效率 | 开发工具、命令行、编辑器、效率配置 | [tools](./tools/) |
| 问题复盘 | Bug、事故、排查过程、经验教训 | [reviews](./reviews/) |
| 面试杂项 | 不属于具体技术栈的面试记录、HR 面、沟通题 | [interview](./interview/) |
| 模板 | 新增 Misc 笔记时复用的写作结构 | [templates](./templates/) |

## 写作约定

每篇 Misc 笔记建议包含：

1. 背景：为什么记录这件事。
2. 核心结论：以后可以直接复用的判断。
3. 过程或来源：结论从哪里来，如何验证。
4. 适用边界：什么情况下不适用。
5. 后续动作：需要继续做什么。

## 文件命名

- 使用小写英文和连字符，例如 `git-worktree.md`。
- 日期型记录使用 `YYYY-MM-DD-title.md`。
- 读书笔记建议使用 `book-name.md`，章节拆分时使用子目录。
